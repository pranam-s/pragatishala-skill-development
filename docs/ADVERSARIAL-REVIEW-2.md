# Second-Round Adversarial Review — pragatishala-skill-development

**Date:** 2026-09-12 · **Reviewer:** second-round adversarial pass (AR2)
**Scope:** the fixes introduced by the first-round remediation (JWT placeholder/entropy validator AR-021, sentence-scoped proficiency scorer AR-029, ambiguous-alias handling AR-030, rate-limit middleware AR-023, dependency majors) plus fresh-eyes passes over the SSE bus, market-insights cache, AI provider fallback, and e2e smoke coverage. Base commit `1a91e31` (tree clean).

**Method:** every finding below was verified by execution against the real code in the backend venv (a throwaway probe script exercising `Settings` validation, `_rule_based_assessment`, `_is_skill_context`, `SlidingWindowLimiter`, and an ASGI-level concurrency harness), or by precise reading with file:line references. No finding is speculative; where behaviour is documented and accepted in an ADR, that is stated and the finding is downgraded or dropped.

## Executive summary

15 findings: **3 high, 6 medium, 6 low**. The headline: **the AR-030 ambiguous-alias fix traded one false-positive family for another.** The sentence-level context gate (`engine.py`) is (a) applied sentence-globally rather than near the alias, so *"At the coding bootcamp I was ready to go."* still invents a Go skill while *"Built a payments service using Go."* — a direct skill claim — now finds nothing, and (b) gated for only 3 aliases (`c`, `go`, `led`), while the same homograph problem survives for `node`, `swift`, `cv`, `.net`, and `lambda` (*"I listen to Taylor Swift"* → iOS Development, beginner). The context regex itself has a missing trailing `\b`, so `know` matches inside *knowledge*, `code` inside *encode* — a sentence about a knowledge-base article manufactures a Leadership skill.

The JWT validator (AR-021 fix) does exactly what ADR-0006 claims — placeholder denylist plus a degenerate-key floor — and my bypass hunt confirms the ADR's own caveat: the floor is a sanity check, not a strength meter. All ten guessable candidate families I constructed (keyboard walks, dictionary concatenations, repeated blocks, tutorial dev defaults, denylist one-character variants) **pass both checks**. ADR-0006 is honest about this; docs/limitations.md and the README are not — that documentation gap, plus the denylist's narrowness, is the finding.

The rate-limit middleware (AR-023 fix) is **functionally correct**: the sliding window is atomic under concurrency (10 concurrent requests at limit 2 → exactly 2×200, 8×429), Retry-After math is right, and all 7 rules match real registered routes (verified against FastAPI 0.141's lazily-included routers). The gaps are operational: unbounded key-space growth, and a per-peer-IP key with no trusted-proxy story shipped (ADR-0007 defers to a "deployment guide" that does not exist).

Verified good: token decode hardening, SSE backpressure design, AI fallback confidentiality (no internals leaked to clients), market-cache cold-start race handling, prompt-injection fencing, and an e2e smoke that covers ownership boundaries.

## Verified good (adversarially checked, held up)

- **Rate-limit concurrency correctness** — `SlidingWindowLimiter.check` performs test-and-append with no `await` between them, so the single event loop serializes it: an ASGI harness firing 10 concurrent requests at limit 2 returned exactly `[200, 200, 429×8]`. No TOCTOU window exists in-process.
- **Retry-After math** — `ceil(oldest_hit + window − now)`, minimum 1: probe observed 60 → 30 (at +30 s) → allowed (at +65 s). Rejected requests are not re-counted (rejection cannot extend the lockout). Monotonic clock used. `limit ≤ 0` disables a bucket and is validated non-negative in Settings.
- **Rule coverage** — all 7 RULES match real registered routes (auth login/register/refresh, POST assessments, learning-paths generate, resumes generate, GET market/insights); the SSE route is deliberately unthrottled. Verified by flattening FastAPI 0.141's lazily-included routers (`_IncludedRouter`) — note `app.routes` iteration needs unwrapping on this FastAPI version; naive route walkers silently see zero API routes.
- **Token decode hardening** (AR-025) — decode pins the algorithm to the configured HS-family literal, enforces `iss`/`aud`, requires `exp, iat, sub, jti`, and checks `type` per endpoint; refresh/access confusion is rejected.
- **Degenerate keys are actually rejected** — `"A"×40` fails boot (distinct=1); the validator fires at `Settings` construction, before any bind.
- **SSE backpressure design** — per-subscriber `asyncio.Queue(maxsize=100)`; publishers use `put_nowait` and drop on full (never block AI work); `unsubscribe` runs in a `finally`; `wait_for(queue.get(), timeout=keepalive)` cancellation does not consume an event; keep-alive comment frames keep proxies from idling out the connection.
- **AI fallback confidentiality** — on provider failure the full `AIError` (which can embed the base URL and HTTP status) reaches only the server log; clients receive the schema-validated rule-based result plus the intentional `engine_used` disclosure. No stack traces, URLs, or provider internals cross the API boundary. `build_provider` fails fast at startup when an explicit provider is selected without its key.
- **Market-cache cold-start race** — concurrent first requests for a role are handled via the `IntegrityError` rollback-and-serve-winner path; role keys are normalized (lower-cased, whitespace-collapsed) so cache keys are stable; `refreshed_at` has a column default so the insert path cannot persist NULL.
- **Prompt-injection fencing** — every system prompt carries the `_UNTRUSTED_DATA_NOTE` and all user-controlled text is wrapped in `<user_data>` tags (engine.py:739-747), with residual risk documented in docs/limitations.md.
- **e2e smoke** — covers duplicate-register 409, cross-user 404 ownership boundary, SSE unauthenticated 401, and refresh rotation; runs against a live server with no test-only backdoors.
- **AR-035 frontend cleanup** — scoped to two catch blocks in `ProfilePage.tsx`/`SkillAssessment.tsx` (light review; no behavioural surface found). Deep frontend re-review was explicitly out of scope for this pass.

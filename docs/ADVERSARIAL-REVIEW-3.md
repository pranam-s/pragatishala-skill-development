## Executive summary

11 findings: **1 high, 6 medium, 4 low**. The headline: **the AR2-003 alias-proximate gate downgraded the most common leadership phrasing to near-unusable.** *"I led the migration and I am an expert in Python."*: round 1 scored this Leadership=expert, the fix scores Python and **drops Leadership entirely**: the rescue words (`team` within 3 tokens, or a context word within 24 characters) are absent where `led` sits, even though "expert" is in the same sentence. *"I led multiple projects end to end."* produces **no skills at all** (and never did) (round 1 dropped it too; see AR3-001 for the honest split between regression and cemented under-detection). Either way, after two remediation rounds the Leadership detector fires on *"led"* only when `team`, `engineers`, `development`, or a level word happens to sit within 24 characters, not on "I led the migration/projects/rollout/initiative", the dominant resume phrasing.

Second: **the AR2-004 abbreviation fix is only half-verified against its own example.** The sentence split is gone, but in *"Expert in web technologies, e.g. Python and SQL."* the level word still binds only to the first-listed skill (`_scope_bounds` clips at every other mention): Python=expert, **SQL=beginner**, exactly the mis-score AR2-004 said it fixed. The same asymmetry holds for every comma list (*"Expert in Python, SQL, and Java."*).

Third: **decimal years are parsed as their fraction digits.** `_EXPERIENCE_PATTERN` matches `\d{1,2}` immediately before "years", so "3.5 years" scores as **5**, and *"0.5 years with Python so far."* yields Python=**expert**. The AR2-006 fix rewrote this exact regex (adding the `unit` group) without closing it.

The homograph class AR2-002 called high is narrowed, not closed: five everyday sentences still fabricate skills (*"I'm the go-to person for databases."* → Go; *"Updated my CV with new skills."* → Computer Vision; *"I wrote a lambda expression in my code."* → AWS; *"The swift development of the feature…"* → iOS Development; *"A node in the database cluster failed."* → Node.js), because any context word inside the 24-char window vouches for the alias. The `refresh` flag added for AR2-014 converts the 24 h cache from an LLM-cost control into an opt-out for any authenticated user (15 billable calls/min forever), and the `model_used` column added for AR2-014 ships with **no migration path**: `create_all` never alters existing tables (verified empirically), so any pre-upgrade database 500s on every market request.

What held up under attack: the substring placeholder check, the per-condition low-entropy messages, the rate-limit bucket sweep (600 stale keys swept on schedule; rejections cannot starve the sweeper), SSE sequence stamping (strictly ordered under 200 concurrent publishes; gaps from backpressure are genuinely detectable), the C++/C# longest-match disambiguation, the `e.g.`/`Dr.` masking, and the honest residual-risk documentation for the JWT-secret floor (limitations #13, deployment.md §4): every guessable secret family I re-probed (keyboard walks, hex runs, repeated blocks, top-password concatenations) still passes both checks, exactly as that documentation now discloses.

## Verified good (adversarially checked, held up)

- **AR2-003 proximity gate core cases**: *"At the coding bootcamp I was ready to go."* → no skills (the old false positive is dead; `coding` lands 25 chars before `go`, just outside the window); *"Built a payments service using Go."*, *"Leading a Go team at a startup."*, *"I know C"* → Go/C detected. The window edge cuts both ways (see AR3-004/AR3-008) but the AR2 repros pass.
- **C++/C# disambiguation**: *"I know C++"* → C++ only (not C); *"C# development experience"* → C# only (not C). The longest-span-first rule in `_mention_spans` correctly eats the overlapping `c` span; the gate extension to `node/swift/cv/.net/lambda` does not regress these.
- **AR2-004 masking mechanics**: `_abbreviation_mask` is same-length, so masked sentence bounds and unmasked spans stay coordinate-aligned; `Dr.` no longer splits *"Dr. Smith says I led the migration…"* (the hearsay Leadership claim from AR2-005 is now correctly *not* scored there: the proximity gate incidentally fixed that hearsay case, and the residual hearsay disclosure at `docs/limitations.md:46` covers the rest, verified: the 'SQL guy' quote example still yields SQL=expert as documented).
- **AR2-006 fix on its own repro**: *"I spent 3 years in support, then moved to Python development."* → Python=beginner; correct two-figure attribution (*"9 years with Rust and 2 years with Go."* → Rust=expert, Go=intermediate); trailing figures (*"Python, 6 years."* → expert); *"12+ years of Java."* → expert.
- **AR2-007 substring placeholder check**: `"1change-me-at-least-32-bytes-long2345678"` rejected; a real-looking secret embedding the `.env.example` placeholder (`…change-me-generate-a-real-secret-with-secrets-token-urlsafe…`) rejected. No false-positive risk for `secrets.token_urlsafe` output (substring collision is computationally nil; control token accepted).
- **AR2-012 per-condition messages**: `"a"*40` → "too few distinct characters"; `"a"*30 + "bcdefghijkl"` (12 distinct, 1.85 bits/char) → "character distribution too flat (too repetitive)". Each message names a true condition.
- **JWT floor residual risk is now honestly documented**: every guessable family I re-constructed still passes both checks (keyboard walk ×2, hex run ×4, `Sunshine-Rain99!`×3, top-password concat `iloveyou1234administratorletmein5678`, alphanum run ×2), and `docs/limitations.md` #13 plus `docs/deployment.md` §4 now say exactly that ("a sanity floor, not a strength meter; the generator is the control"). The AR2-008 posture (keep the floor, disclose, generate with `secrets`) is internally consistent; no bypass of the *documented* contract exists.
- **AR2-010 bucket sweep**: 600 distinct stale keys + 512 fresh allowed checks → sweep fired on schedule, all 600 stale keys dropped (`remaining=0`); 600 consecutive rejections do not advance `_checks`, so a lockout cannot starve the sweeper, and rejections never grow the map (new keys are created only on the allowed path).
- **AR2-011 slash matching**: `bucket_for("POST", "/api/v1/auth/login/")` → auth; `//` suffixes normalize too. The remaining defect is only the redirect double-count (AR3-009).
- **AR2-013 SSE sequence stamping**: 200 concurrent `publish` tasks to one subscriber: exactly the first 100 delivered (queue maxsize), **strictly ordered 1..100** (the lock-to-`put_nowait` span is synchronous, so no interleave can reorder); two interleaved publishers → strictly increasing seqs; drops from backpressure leave a detectable gap; the SSE frame carries `id: <seq>` (e2e asserts `^id: [0-9]`). Zero-subscriber publishes advance the counter harmlessly (`_sequences` costs one small int per user; never pruned; noted, not actionable).
- **e2e smoke AR2-015 additions verified by reading**: live SSE event grep (`event: learning_path.completed` + `^id: [0-9]`), second market call asserting `cached=True`, tampered refresh 401, and a bounded 12-iteration 429 loop that fits inside the auth budget: 7 auth hits accumulate before the loop (register ×2, login ×2, refresh, tampered refresh, second-user register/login counted separately → the loop's 4th–5th iteration crosses the limit of 10, well within the 12 tries). Residual: the bucket stays hot afterwards (AR3-010).
